# 08 · 测试报告 / 发布门禁

## 输入

```text
【运行结果】
.testforge/runs/run-results.json

【用例验证】
.testforge/reports/validation-report.json

【门禁】
.testforge/reports/gate-report.json

【覆盖矩阵】
.testforge/cases/coverage-matrix.json

【输出】
.testforge/reports/report.md
```

## 任务

生成一份给**研发、QA、产品**共读的测试报告，包含：

1. **结论摘要**：是否建议发布；阻塞项数量；最大风险。
2. **运行概览**：各套件通过/失败/超时/错误、耗时。
3. **用例质量**：总数、错误/警告、重复、AC 覆盖率、可自动化比例。
4. **质量门禁**：每项指标、阈值、结果；失败项要解释影响。
5. **未覆盖项**：AC、风险、技术、平台。
6. **失败详情**：按套件分组；每条给分类（产品/用例/环境/flaky）、证据、负责人。
7. **缺陷候选**：产品 bug 的复现步骤、期望、实际、影响。
8. **flaky 分析**：哪些用例不稳定、可能原因、建议。
9. **下一步**：按优先级列出 3-5 个行动项。

## 写作要求

- 先结论，后细节；不要一上来贴日志。
- 数字要可核对（来自 JSON，不要手写）。
- 失败项必须带“下一步”，不要只报错。
- 对不确定的结论标注“待确认”，不要下绝对判断。
- 不要暴露密钥、token、PII；日志中的敏感信息要打码。

## 发布建议规则（示例）

- `BLOCK`：P0 用例失败、AC 覆盖率 < 阈值、门禁失败、存在未分类的产品 bug。
- `CONDITIONAL`：仅 P2/P3 失败、flaky 在阈值内、有明确规避方案。
- `GO`：全部门禁通过，无阻塞缺陷，覆盖率达标。
