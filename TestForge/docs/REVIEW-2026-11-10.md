# TestForge 套件审查报告

> 审查时间：2026-11-10  
> 审查对象：`TestForge/`（CLI、Schema、Prompts、Skills、Subagents、Commands、Templates、Adapters、CI、Examples）  
> 审查方式：静态审查 + 交叉引用检查 + 人工推演示例数据。  
> **限制**：本环境 PowerShell 被拒绝，未能实际执行 `python testforge.py`。以下“已修复”指代码/文档已改，仍需你本地跑一遍验证。

---

## 1. 总体结论

**评级：POC 可用，生产前需项目化验证。**

| 维度 | 评价 |
|---|---|
| 结构完整性 | 好：CLI、9 prompts、7 skills、7 agents、7 commands、4 schemas、templates、adapters、CI、3 examples 齐全 |
| 核心链路 | 好：pack → 需求分析 → 用例设计 → E2E/API/代码 → 评审 → 执行 → 门禁 → 报告 |
| 确定性验证 | 中上：Schema/覆盖矩阵/去重/覆盖率/变异分有脚本；但默认 Schema 校验是手写规则，完整校验需 `--schema` + `jsonschema` |
| E2E 可用性 | 中上：Playwright/Gherkin 模板完整；示例无真实服务，不能端到端跑 |
| 安全 | 中：有文档和最小权限建议；缺自动脱敏/密钥扫描 |
| 可维护性 | 中上：单文件 CLI、stdlib、JSON 配置；扩展点清晰 |
| 可执行性 | **未验证**：本环境无法执行，需本地 smoke test |

## 2. 高优先级发现（均已修复）

| ID | 问题 | 影响 | 修复 |
|---|---|---|---|
| H-01 | `validate` 只要求 `id/title/source_refs/expected_result`，未校验 `technique/priority/type` 枚举、重复 ID、空 source ref、空 expected | 错误用例可能“校验通过”，门禁失真 | 增加必填/枚举/唯一性/空值检查；E2E 用例单独识别（按 `feature` 字段） |
| H-02 | E2E 用例被当成普通用例校验，因缺 `technique/type` 报错 | `e2e-cases.json` 无法通过 validate | `is_e2e = bool(case.get("feature"))`，E2E 只要求 `feature/priority/test_data` 等 |
| H-03 | `gate` 的 `flaky_rate` 永远不存在于 `run-results.json`，flaky 门禁空转 | “flaky ≤ 2%”只是文档承诺 | `run` 支持 suite `reruns`，计算 `flaky`/`flaky_rate`；`gate` 真正读取 |
| H-04 | `gate` 的 coverage/mutation/validation 相对路径按 cwd 解析 | 从不同目录运行会找不到报告 | 统一按 `testforge.config.json` 所在目录解析 |
| H-05 | `init` 不生成 `.testforge/.gitignore` | `context/` 可能含敏感文档，被误提交 | `init` 写入 `.testforge/.gitignore`（忽略 context/runs/reports） |
| H-06 | Gherkin 导出声明 `# language: zh-CN` 但使用英文关键字 | 部分 Gherkin 解析器报错 | 去掉语言指令，使用默认英文关键字 |
| H-07 | README 自检用 `^` 续行，PowerShell 实际是反引号 | 用户复制执行会失败 | 改为单行 PowerShell 命令，并注明 bash 用 `python3` |
| H-08 | 示例 service 用例里写了 `"https://example.com/" + "a"*2031`（Python 表达式） | JSON 非法，示例无法加载 | 改为合法占位字符串（审查前已修，本次确认） |

## 3. 中优先级发现（已修复）

| ID | 问题 | 修复 |

## 5. 建议的本地验证顺序

```powershell
cd "D:\AI世界\4.Claude世界\1.调研\1.用例生成和自动化测试\TestForge"

python testforge.py --help
python testforge.py doctor --config config/testforge.config.example.json

python testforge.py validate --cases examples/platform/test-cases.sample.json --requirements examples/platform/requirements.json --out examples/platform/validation-report.json
python testforge.py matrix --cases examples/platform/test-cases.sample.json --requirements examples/platform/requirements.json --out examples/platform/coverage-matrix.json
python testforge.py export --cases examples/platform/test-cases.sample.json --format markdown --out examples/platform/test-cases.md
python testforge.py export --cases examples/platform/e2e-cases.sample.json --format gherkin --out examples/platform/e2e.feature
python testforge.py run --manifest examples/platform/run-manifest.sample.json --dry-run
```

预期：

- `validate`：`errors=0`；AC 覆盖 3/4（AC-004 故意未覆盖）。
- `matrix`：`AC-004` 标记 `UNCOVERED`。
- `export gherkin`：一个 `Feature` 下两个 `Scenario`。
- `run --dry-run`：3 个 suite 均为 `dry-run`。

如出现语法/路径/JSON 错误，优先检查 Python 版本（建议 3.11）和配置文件路径。

## 6. 生产化前的 5 个动作

1. 用真实仓库跑 `pack`，检查 PDF/表格/代码切块质量。
2. 用 1 个模块跑 `requirement-analyzer`，人工确认 Gap，统计采纳率。
3. 把 `commands` 换成真实测试命令，跑 `run` + `gate`。
4. CI 加 `--schema` 和 `jsonschema`，把 `gate` 作为合并门禁。
5. 加 secret/PII 扫描，禁止 `.testforge/context/` 入库。

## 8. 第三轮：通用内核 + packs 实现审查（2026-11-12）

批次 1 已实现并验证：

- `core/`：config、packs、detect、scaffold、export_formats、mcp、prompt。
- `packs/`：`python-service`、`java-service`、`cpp-cli` 完整；`frontend-web`、`k8s` 骨架。
- `profiles/`：platform、python-service、java-service、cpp-cli、web。
- CLI：`init --stack/--surface/--detect/--list-packs/--dry-run/--upgrade`、`scaffold`、`export testrail|xray`、`mcp`、`prompt`。
- 栈感知：`pack` 上下文带 `stack_id`/`pack`；`validate`/`matrix` 支持 `--stack` 和 `by_stack`；`run` 支持 `kind=test|report`、`--with-reports`；`gate` 按 stack 解析覆盖率/变异并支持 `--allow-missing-reports`。
- 测试：`TestForge/tests` 共 **37 个 unittest 全部通过**。
- Python 示例：`pytest` **5 passed**；scaffold 生成 3 个 pytest 骨架，**3 skipped**。
- Java/C++ 示例：本机 PATH 中没有 Maven/JDK/CMake/g++，未执行编译；pack 契约、模板存在性、scaffold 已由 unittest 覆盖。

**第三轮仍存在的限制：**

- Java/C++ 示例需要在有 Maven/JDK/CMake/GoogleTest 的环境跑一次。
- `frontend-web`/`k8s` 只有骨架，完整模板在批次 2。
- `gate` 的 PIT XML 解析是简化版（KILLED/SURVIVED），未处理所有状态。
- `mcp` 的 `run`/`gate` 默认只读；写入需 `--allow-write` 或 `allow_write=true`。
- 覆盖率/变异解析器覆盖常见格式，但未在所有真实项目验证。
